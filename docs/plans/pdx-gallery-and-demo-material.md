# PDX gallery and demo material

## Status

Complete. The approved seven-image gallery and 101-page demo material are published in `pf-assets`, and the portfolio's canonical PDX record now uses them.

## Goal

Replace PDX's single stale portfolio image with a truthful product gallery and add a stable public link to a substantial Computer Networks study-material PDF generated by the live PDX pipeline.

## Context

PDX now runs as a free BYOK product at `https://pdx.sdey.me`. The portfolio still describes the retired credits, Dodo billing, Gemini, and `usepdx.tech` version. Portfolio-owned assets live in the public `pf-assets` R2 bucket and use immutable, versioned object keys.

## Scope

- Capture desktop portfolio images for the landing page, dashboard, BYOK settings, theory-generation workflow, completed-material history, restored pricing page, and generated PDF output.
- Generate a Computer Networks theory guide through production PDX with Nebius `deepseek-ai/DeepSeek-V4-Flash-0731`.
- Verify PDF integrity, page count, visual quality, and durable storage.
- After user approval, upload versioned gallery images and a stable public PDF copy to `pf-assets`.
- Update the canonical PDX record in `src/lib/project-boxes.ts` with current architecture, live URL, images, and a visible demo-PDF link.

## Non-goals

- Redesigning the portfolio popup or PDX UI.
- Changing the portfolio's project slug, bento ordering, or chat architecture.
- Making PDX's private R2 bucket public.
- Deploying either repository without separate authorization.

## Chosen approach

Use the real production PDX workflow and a controlled disposable account so screenshots show coherent authenticated state. Keep provider credentials only in process memory and PDX's encrypted credential store. Publish the approved artifacts under new immutable `projects/pdx/` keys in the existing public portfolio bucket. The portfolio will link to the public copied PDF rather than an expiring PDX download URL.

## Implementation phases

1. Inspect auth, BYOK, generation, storage, and screenshot boundaries.
2. Generate and validate the Computer Networks PDF.
3. Capture and inspect the gallery, then wait for explicit approval.
4. Upload approved assets and update the portfolio record.
5. Run focused lint, type checking, production builds, and modal checks.

## Validation

- Every screenshot is a readable 16:9 desktop image with no secret or disposable credential visible.
- Browser reports return successful page loads; unexpected console and request failures are reported.
- The PDF opens, has a valid page tree, contains meaningful text on sampled pages, and is close to 100 pages without padding or duplicated filler.
- The public PDF URL returns `200` with `application/pdf`.
- The PDX popup shows the approved gallery in order and exposes the live site, source, and demo PDF without breaking mobile or chat behavior.

## Outcome

- Published seven versioned PDX images and the 101-page Computer Networks study guide under `projects/pdx/` in the public portfolio bucket.
- Updated the PDX record with the current free BYOK positioning, architecture, live domain, gallery, and demo-material link.
- Confirmed all seven modal images load at their natural dimensions and the public PDF responds with `200`, `application/pdf`, and inline viewing metadata.
- Passed portfolio lint, TypeScript checking, and the Next.js production build. Lint retains one unrelated pre-existing warning in `src/actions/contact-form.ts`.

## Risks

- Model output length may produce materially fewer or more than 100 pages. Adjust the syllabus scope once if the first complete result misses the useful target range.
- Chromium rendering can fail on malformed generated Mermaid, Chart.js, SVG, or mathematics. Sample pages and logs before publication.
- The existing portfolio worktree contains unrelated documentation changes. Do not stage or commit them with this task.
